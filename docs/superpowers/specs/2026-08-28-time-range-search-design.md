# 时间范围搜索 `time:` 统一语法

> 状态:设计定稿(2026-08-28)
> 关联需求:time-range-search(vault: ~/Obsidian/10-Projects/logview/time-range-search/)

## 背景

现有 `after:HH:MM` / `before:HH:MM` 三大缺陷:
1. 仅时分、忽略日期与秒——`logview file` 读多日归档时,"每日窗口"语义匹配所有天的同时段,不是用户想要的
2. 跨天语义歧义:follow 挂一夜,昨晚行会被 `after:09:00` 意外匹配
3. 语法记忆负担(after/before 两个前缀)

## 设计

### 语法(唯一入口 `time:`,旧 after/before 移除)

```
time:>09:00                今天 09:00 之后
time:<10:00:30             今天 10:00:30 之前(秒级可选)
time:>08-26                8月26日 00:00 之后(年取当年)
time:>08-26_09:00          8月26日 09:00 之后
time:>2026-08-26_09:00:30  完整时间戳
time:>-10m  time:<-1h  time:>-30s   相对此刻(解析为绝对时刻)
time:>09:00 <10:00         区间(与其它条件 AND 组合)
```

### 解析(tokenize → termNode)

- `fieldPrefixes` 增加 `time:`,移除 `after:` / `before:`
- 分词规则:`time:>X` 与裸 `>X` / `<X`(X 为合法时间值)都识别为时间比较 token——因此 `time:>09:00 <10:00` 自然成为两个条件;裸写时仅当值部分能解析为合法时间才走时间语义,否则按普通关键字
- 值部分按结构识别(无歧义,不猜):
  - `>` / `<` 前缀取比较方向;`time:` 前缀后缺失比较符 → 降级关键字
  - `-` 开头 + 数字 + 单位(m/h/s)→ 相对时刻(解析时锚定 time.Now,存绝对时刻)
  - 含 `_` → 日期 + 时间;仅 `-` 分隔数字段 → 纯日期
  - 纯 `:` → 时分或时分秒
  - 日期年缺省取解析时当年
- 格式非法 → 整词降级为普通关键字搜 message(沿用现有兜底)

### 匹配(单一语义:绝对时刻比较)

所有形式解析为 `time.Time`,`line.Time` 与之直接比较(严格 > / <):
- 纯时分 → 今天 00:00 + 时分(秒缺省 00)
- 相对 → now ± 时长
- `line.Time.IsZero()`(无时间字段/解析失败的行)不参与匹配 → 排除

### UI 反馈

- `TimeRangeHint()` 升级:显示 `[时间: 08-26 09:00 ~ 10:00]`、`[时间: > 最近10分钟]` 等实际解析结果
- README 搜索语法段重写;帮助弹窗如有提及同步

### 兼容性(breaking)

- `after:` / `before:` 语法移除,输入将降级为关键字搜索(与其它非法字段前缀行为一致)
- 项目个人使用 + 刚发 v0.15.x,无存量用户迁移负担
