# 源选择器（k8s / 本地 / SSH 远程日志）

## 目标
TUI 内按 `o` 呼出源选择器，像文件管理器一样**逐级浏览**选择日志源：k8s（context → namespace → 资源）、本地（目录浏览）、SSH（主机 → 远程目录浏览），无需退出重启。

## 约束
- 三类源全部实现 LogStream 接口（k8s/本地已有，SSH 已实现）
- SSH 认证依赖系统 ssh；k8s 依赖系统 kubectl（context 切换 = `kubectl config use-context`）
- 浏览式交互取代纯输入：候选列表可进入子级（Enter 进入目录/ns/context）与返回（Backspace/u 返回上级）
- 保留手动输入作为兜底（路径/ns 直接输入仍有效）

## 模块拆解
- K8s tab 三级浏览（sourcepicker）：context 列表（`kubectl config get-contexts`，当前项高亮）→ namespace 列表（`kubectl get ns`）→ 资源多选（deploy/sts/pod 分组，Space 勾选，Enter 确认）
  - context 选择即执行 `kubectl config use-context`（全局生效，与 kubecntx 行为一致）
- 本地 tab 目录浏览器（sourcepicker）：列出目录内容（文件夹在前、日志文件在后），Enter 进目录 / 打开文件，Backspace 返回上级，`~` 展开，手动输入路径仍可直达
- SSH tab 两级浏览（sourcepicker + stream/ssh.go 辅助）：主机列表（过滤保留）→ 连接后 `ssh host ls -F dir` 列远程目录（缓存会话内连接），Enter 进目录/选文件，Backspace 返回
- 状态机（sourcepicker.go）：每个 tab 独立面包屑（pickerCrumb）+ 浏览深度（level），候选异步拉取（tea.Cmd + msg 回填，kubectl/ssh/ls 共用）

## 关键决策
- context 切换直接改 kubeconfig（use-context）而非 --context 参数透传：与用户其它 kubectl 工作流一致，选择一次全局生效
- SSH 浏览复用 `ssh host ls` 每次单发：不维护长连接（简单可靠），交互式目录跳转延迟可接受（每次 <1s）；BatchMode 保证不挂起
- 本地/SSH 目录列表混合展示文件夹与文件（文件夹带 / 后缀高亮）：Enter 行为按类型分派，无需切换模式
- namespace 作为 K8s 第二级而非输入框：集群 ns 数量有限且可列举，浏览比输入快
- 保留手动输入兜底：输入框仍存在（ns 输入、路径输入、ssh host 输入），浏览与输入双轨

## 风险
- `kubectl config use-context` 修改全局状态：用户可能有自动化依赖当前 context——在选择器顶部显示当前 context 名，切换前可见
- SSH ls 延迟（跨境主机慢）：候选区显示「加载中…」，Backspace 可取消返回
- 远程 ls 输出注入（文件名含换行）：用 `ls -1 -F` + 忽略异常行兜底
- 三级浏览状态机复杂度：每级独立 cursor/candidates 数组，Backspace 出栈，避免相互覆盖 bug
