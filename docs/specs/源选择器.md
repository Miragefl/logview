# 源选择器（k8s / 本地 / SSH 远程日志）

## 目标
TUI 内按 `o`（open）呼出源选择器，可切换 k8s 资源、本地文件、SSH 远程文件三类日志源，无需退出重启。

## 约束
- 三类源全部实现 LogStream 接口（k8s/本地已有，SSH 新增）
- SSH 认证依赖系统 `ssh`（复用 ~/.ssh/config 别名/密钥/跳板），同时支持 rules.yaml 配置常用主机列表
- SSH 读取 = `ssh <host> tail -f -n <N> <file>`（复用 follow 语义）；断线时在日志流中插入错误行提示（不崩 TUI）
- k8s 选择器复用现有 kubectl 发现（completeK8sResource 同源逻辑），namespace 可选
- 切换源 = 销毁当前 stream（cancel + Cleanup）→ 新 stream Start → 清屏（沿用 S-c 清屏语义，用户可自行对比需求）

## 模块拆解
- SSH 数据源（internal/stream/ssh.go）：SSHSource{host, path, tailLines}，Start 起 `ssh` 子进程逐行读；Label = `ssh://host/path`；stderr 错误写入日志流（ERROR 级行）
- 源选择器 UI（internal/tui/sourcepicker.go）：三 tab（K8s / 本地 / SSH）复用统一弹窗模式（inline popup + tab 切换 + 输入框 + 候选列表）
  - K8s tab：namespace 输入 + 资源多选列表（kubectl get 拉取 deploy/sts/pod 候选，j/k 移动、Space 勾选多个，Enter 确认 → NewMultiK8sSource 聚合，每行日志按 pod source 着色区分）
  - 本地 tab：路径输入 + 文件名过滤，候选来自指定目录 ls（默认 ~/logs 或当前目录）
  - SSH tab：主机候选（rules.yaml hosts + ~/.ssh/config 解析的 Host 别名）+ 远程路径输入 + tail 行数
- 源切换（internal/tui/app.go）：新增 `ReplaceStream(src)` —— cancel 旧 ctx、Cleanup、新 src Start、buffer/filter/统计全清、标题栏 label 更新；`o` 键绑定
- SSH 主机配置（internal/parser/rules.go + cmd/root.go 默认 YAML）：`ssh_hosts: [alias1, user@host2]` 可选字段，注入选择器候选
- 候选数据获取：TUI 内用 tea.Cmd 异步执行 kubectl/ssh 查询（避免阻塞渲染），结果经 msg 回填

## 关键决策
- 快捷键 `o` 呼出而非启动选择器：用户直接 `logview tail xx.log` 的既有习惯不变，选择器是增强入口
- K8s 多选列表而非手输 kind/name：多 deploy 对比查看是高频场景（MultiK8sSource 底层已支持），列表勾选比手输两个框快；候选按 kind 分组展示（deploy/sts/pod）
- SSH 用系统 ssh 子进程而非 golang.org/x/crypto/ssh 库：零依赖、免重实现认证（agent/跳板/ProxyJump 全免费），代价是无法拿到结构化错误——用 stderr 兜底
- 三 tab 复用统一弹窗（同搜索弹窗 inline 模式）：与既有搜索/高亮/隐藏弹窗交互一致，无新学习成本
- 主机候选合并 rules.yaml + ~/.ssh/config：前者是用户显式常用集，后者自动发现，去重后排序
- 切换源清屏：混合两个源的日志在时间线上无意义，且 filteredView/bookmarks/统计都按源持有

## 风险
- kubectl/ssh 查询慢或不可用：候选区显示「查询中…/不可用」状态行，不阻塞输入框手动输入
- ssh 主机不可达：Start 后 stderr 出现错误 → 写错误行进日志流 + 弹窗保持可重试
- ~/.ssh/config 解析边界（Include/Match）：只解析顶层 Host 条目（覆盖 95% 场景），复杂配置靠手动输入兜底
- ReplaceStream 与既有 pipe/k8s 流竞争：cleanup 全部走既有 stream.Cleanup() 路径，k8s 已有进程组回收逻辑可复用
