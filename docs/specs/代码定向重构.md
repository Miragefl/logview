# 代码定向重构

## 目标
基于全量代码审查结论，对 logview 做定向重构：修复边界 panic/丢行/静默吞错，删除"建了没接线"的死设施，收敛重复代码，拆解 `tui/app.go` 上帝文件——不推倒重来。

## 约束
- Go 1.26 + bubbletea/cobra/yaml.v3；构建 `make build`，测试 `go test ./...`（见 PROJECT-CONTEXT.md）
- 行为保持：现有测试全绿为准，不新增功能、不改 UI 布局（错误提示文案除外）
- 不做（审查 C 节确认保持现状）：33ms tick 批拉架构、wrapAnsiText 手写状态机换库、stacktrace 全量重算、tail 改 fsnotify、文案国际化、LogStream/Parser 接口规模

## 模块拆解
- Phase 1 bug 修复：stream/buffer 的除零 panic、Stat 空指针、末行无换行丢行；cmd/tui/stream 的 5 处静默吞错
- Phase 2 死设施清理：SearchIndex（只写不读）、热重载死链路（SetReloadFunc 无调用者 + watcher 泄漏）、死样式/死函数/死配置宣传
- Phase 3 去重收敛：4 份手写文本输入编辑、6 处 popup overlay 样板、渲染层成对重复、ansiRe 双份定义、processBatch/processLine 重复
- Phase 4 结构收敛：loadParsers 8 返回值 → Config struct、抽 runTUI、全局可变态入 App、CompileRules 去 panic、cmd 与 AutoDetect 补测试
- Phase 5 app.go 拆分：搜索族（search/highlight/hide）子 model 化，handleNormalKeys（239 行）按功能域拆函数

## 关键决策
- 死设施一律"删"不"接线"：热重载无用户需求，删除即顺带修复 configWatcher 的 fd/goroutine 泄漏
- `error_line_bg` 等死配置键：从默认 YAML 示例删掉宣传，不补实现
- B1 只拆搜索族（三个 handler 高度同构），不追求 8 个模式全部子 model 化
- ansiRe 统一放 `internal/model`（parser/tui 均已依赖 model，不新建 ansiutil 包）
- `model.Level` 与 `LevelStyle` 二选一：保留 LevelStyle（TUI 实际使用），删 model.Level/ParseLevel

## 风险
- app.go 拆分引入行为回归 → 以 tui 现有 55 个用例为回归网，只做函数级搬移不改逻辑，Phase 5 放最后
- 删 WatchRules 连带 fsnotify 依赖移除 → go mod tidy 后确认 go.sum 收敛
- cmd 重构改全局 setter 调用时机 → Config struct 仅聚合传参，ApplyTheme/SetFieldMask 调用点与顺序保持不变
